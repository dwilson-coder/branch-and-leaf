    CSS specificity

    Specificity is not nesting depth

    When two rules target the same element, the browser scores their selectors. The score comes from the selector you write, never from how deep the element sits in the tree.

    Reading a score

    A · ID#main
    B · Classclasses, attributes, pseudo-classes: .note [type] :hover
    C · Typeelements, pseudo-elements: p ::before
    compared left to right

    The first column that differs decides. Columns never carry over: one ID beats any number of classes, and 0-1-0 beats 0-0-11.

    Depth adds nothing

    The tip paragraph inside div.note sits seven levels below <html>. Select it in the explorer to check. Even so, .note p (0-1-1) beats html body main article div div p (0-0-7), because one class outranks any number of element names.

      The cascade

      How CSS decides which rule wins

      A simplified view of the cascade. Each step only runs if the step before it ended in a tie.

      1. Origin and importance

        Where the declaration comes from: browser defaults, user settings or the site's stylesheet. Site styles beat browser defaults. !important moves a declaration into a higher-priority group where the origin order flips.

      2. Cascade layers

        Within one origin, @layer order comes next. Later layers win and unlayered styles beat every layer. For !important the order reverses.

      3. Specificity

        Only now are selectors scored. Compare ID, then class, then type, left to right.

      4. Scoping proximity

        Only when @scope rules compete: the one whose scope root is fewer steps up the tree wins. This is the one step where tree distance counts.

      5. Source order

        Still tied? The declaration that appears last wins.

      !important is not a specificity score

      It changes which cascade group a declaration belongs to (step 1, reversed again in step 2). It adds nothing to the A-B-C score. When two !important declarations land in the same group, specificity compares them as usual.

      Left out for simplicity

      Shadow DOM context, and inline style="" attributes. Inline styles beat selector-based rules of the same origin and importance before layers or specificity are checked. They are a cascade step, not a fourth specificity column.
